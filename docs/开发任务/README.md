# 每次任务开发产物管理 (Development Tasks & Artifacts)

> 📢 **目录定位**：
> 本目录专门用于承接 AI 辅助研发工作流（`explore` 探索设计 ➔ `plan` 任务拆解 ➔ `execute` 编码执行）在每次具体任务开发过程中的过程性产物。
> 与 `docs/` 下其他长期沉淀的系统知识库不同，这里按**具体任务（Task）**进行生命周期管理。

---

## 📁 目录组织与统一结构规范

无论任务大小，全部**保持统一的目录与文件规范**，消除认知负担：
- **小任务**：`tasks.md`（总大盘）+ 单个 `phase-1-<名称>.md`
- **中大型任务**：`tasks.md`（总大盘）+ 多个 `phase-1-...`, `phase-2-...`

```text
docs/开发任务/
├── README.md                          # 本说明文件与目录规范
├── 模版-YYYY-MM-DD-主题/              # 任务标准模板
│   ├── 架构图.md                      # /explore 产物：四张图（场景树、拓扑、数据流、状态机）+ 唯一判据表
│   ├── design.md                      # /explore 产物：技术方案设计、边界条件、未决事项
│   ├── tasks.md                       # /plan 产物：【总任务大盘】现状基线、阶段状态表、全局里程碑与阻塞登记
│   └── phase-1-子阶段模版.md          # /plan 产物：【执行清单】原子任务五行条目与实测证据回填
└── YYYY-MM-DD-任务名称/               # 实际任务开发目录示例
    ├── 架构图.md
    ├── design.md
    ├── tasks.md                       # 统领各 Phase 状态的大盘总表
    ├── phase-1-核心逻辑.md            # 具体执行清单（小任务仅此一个）
    ├── phase-2-核心接口.md            # （若有后续阶段依次扩展）
    └── phase-3-前端呈现.md
```

---

## 🔄 工作流与产物对应关系

| 工作流阶段 | 触发指令 | 产物文件 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **阶段 1：探索与设计** | `/explore` | `架构图.md`<br>`design.md` | 理清业务场景分支、系统架构拓扑、端到端数据流转、状态机与唯一判据表；选档依据、设计方案、边界与未决。 |
| **阶段 2：任务清单拆解** | `/plan` | `tasks.md`<br>`phase-*.md` | `tasks.md` 盘点现状基线与划分 Phase；将具体实现拆解到各 `phase-N-*.md` 中（五行标准格式）。 |
| **阶段 3：执行与交验** | `/apply` | 实时回写 `phase-*.md` 与 `tasks.md` | 一次一条推进，实测取证（`[ ]` ➔ `[~]` ➔ `[x]` 并附真实命令输出），阶段完成后更新 `tasks.md` 大盘。 |
