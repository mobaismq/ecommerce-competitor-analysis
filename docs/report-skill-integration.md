# 2026-10-20 报告生成模板接入

「市场 → 竞品分析 → 分析报告」中的「生成报告」现在使用 `ecommerce-analysis-report-generator`，逐商品生成八模块报告。已有报告点「重新生成」后更新；失败时保留旧报告。

## 使用方法

1. 完成采集，确认「查看采集数据」有商品。
2. 在报告列表点击「生成报告」，保持页面打开，等待商品进度完成。
3. 点击「查看报告」，阅读每件商品的八个模块和证据。可展开图片 OCR、评价情感和结论来源。
4. 通过「导出 Markdown」或「导出 JSON」保存完整报告。文件写入应用数据目录下的 `ecommerce/users/<userId>/reports/<reportNo>/`。JSON 包含结构化证据和解析结果。

八个模块依次是：数据源可用性概览、商品标题分析、商品核心卖点、使用人群画像、购买人群画像、产品使用场景、用户诉求及痛点、分析局限与建议。价格带由实际价格计算，作为批次附加统计。

## 数据与模型

- 报告读取客户端本机 SQLite 的 ProductSnapshot、ProductSkuSnapshot、ProductReviewSnapshot、ProductQaSnapshot；问答包含回答。登录认证仍由后端负责。
- 图片优先从采集记录 `rawJson.sourceData` 指向的本机导出目录读取实际字节；只允许应用数据目录内的图片。远程图片 URL 使用当前配置的视觉模型读取。
- 每商品最多选取 2 张主图、2 张详情图、1 张 SKU 图；原文件单张最多 10 MiB，总图片输入约 28 MiB。图片数量、读取失败与选样限制会进入报告。
- 本机图片送视觉模型前读取真实尺寸：长图按 2048 像素长边、96 像素重叠分段；每张最多 16 段，超出时等比缩小而不截掉尾部。普通大图等比缩小至 2048 像素以内，解码上限 8000 万像素。只生成推理副本，采集原图不变；Sharp 及对应平台原生库在安装包中解包加载。
- 每次视觉请求最多 4 段。图片被拒或返回格式无效时单独重试对应请求中的图片，保留其余成功解析；鉴权或限流错误停止后续视觉请求。分段结果合并回原图 ID，图片使用数按原图计数，部分分段缺失和具体失败原因写入报告局限。旧报告不会因修复自动改写，需要重新生成才能更新解析结果。
- 评价去除空内容及默认好评后，均匀抽取最多 120 条；问答最多 80 条，每条文本最多 1200 字符。页面显示输入样本数和解析结果。
- 先由视觉模型单独解析图片与 OCR，再将解析结果和文本资料交给文本模型生成完整报告。文本与视觉模型沿用应用已有个人/默认供应商配置，不在 Skill 内保存密钥。支持 OpenAI 与 Anthropic 兼容协议，Anthropic 本机图使用 base64 source。
- 视觉请求失败或无法返回有效解析时去掉图片输入，改用文本资料，报告标明图片不可用；不能把图片文件名当成图像内容。
- 同类评价多条不增加来源种类。结构化证据按实际来源类型计算「单源推断 / 双源印证 / 多源印证」。未知来源 ID、无效 JSON、缺少八模块的结果不会保存成功。
- 供应商临时错误、限流或超时仅重试失败阶段一次，已完成的图片解析会复用。最多同时分析两件商品；全部完成后事务更新报告及附表，避免只保存一部分。重新生成使用原采集批次，并产生新报告编号，避免复用旧导出文件。

## 主图与详情页策划工作台

分析报告列表展示批次数、当前页主图/详情脚本数、采集数据量与策划状态。已有报告通过「查看出图方案」进入新工作台；尚未生成策划的批次可生成或更新报告。

- 详情采用页面内的文档布局：左侧展示参考商品、数据范围与七项目录；右侧依次为重点与行动、竞品池 Top 10、好评卖点 Top 3、主图方案、详情页方案、制作准备与依据、竞品研究资料。目录定位章节并随阅读位置更新，报告不使用弹窗。
- 「竞品池 Top 10」读取当前报告批次的采集快照（最多100件），按采集销量或价格排序后展示最多10件，以商品缩略图、紧凑对比表和价格条形图呈现；少于10件时展示实际数量，销量不当成月销量，缺失评分不使用店铺评分代替。「好评卖点 Top 3」只聚合已存正面评价中的相同解析要点，以横向条形图显示提及次数，同一商品同一评价同一要点只计一次；同时标注解析样本范围，不换算全量好评率，原文按需展开。每条好评依据显示来源商品缩略图、名称及评价样本序号；完整名称、商品 ID 和解析来源 ID 可悬停核对，名称缺失时才回退至商品 ID，复制与导出也标注商品名称。两个模块也进入完整复制与 Markdown/HTML 导出。
- 报告配色对齐左侧导航和采集页：品牌蓝 `#3388ff` 用于按钮与交互，目录选中态沿用导航的浅蓝 `#e4f3ff`，页面背景沿用 `#f4f7fb`，标题为 `#0a1b39`，卡片为白底。模块通过浅蓝/浅灰标题栏、编号、细边框和留白区分，正文保留深色粗体重点。素材、评价、单品分析等子模块使用独立折叠卡片，展开后仍能辨认层级。
- 阅读重点通过字号和粗细区分：结论用大号粗体，行动标题与核心文案用深色粗体，说明和依据保持常规字重。主图与详情页加宽核心文案列，用浅灰底和行间距引导扫读；研究资料中的评价要点、建议动作也突出显示。
- 主图和详情页章节分别提供「去生成主图」「去生成详情图」，跳到商品主图 `/product-sets` 或详情图 `/aplus`，自动选中当前报告，并将对应章节的文案、画面说明、素材条件及使用边界填入生图表单。跳转只准备表单；用户上传我方商品原图并确认设置后再开始生成。主图表单不会被历史批次或旧版卖点摘要覆盖；跳转参数使用一次后移除，后续已生成批次仍按原逻辑恢复。
- 主图与详情脚本统一为每图一份制作方案，在同一表格行对照任务、文案、画面和素材要求，支持单张或整组复制。相同或仅有格式差异的画面描述会合并，其他制作细节在对应行内按需展开；复制与 Markdown/HTML 导出使用相同合并逻辑，不通过相似度猜测并丢弃数值、否定词等约束。「复制完整报告」同时包含已存单品全文。
- 页面默认只突出结论、优先行动标题、核心文案和一行画面方向；「方案」在原行展开完整目标、画面、素材、补充说明与依据，也支持整组展开。行动解释、长篇评价、研究全文与证据默认收起，点击依据时自动展开并定位对应原文；展开状态不影响完整方案复制与报告导出。已有报告直接按新结构显示，无需重新生成模型内容。
- 目录和依据定位仅滚动报告容器，不调用会连带滚动外层布局的 `scrollIntoView`；末尾章节按容器边界定位，点击选中状态保留到实际滚动后再跟随阅读位置。折叠内容或视口尺寸变化时重新计算位置，避免最后一项错选及应用导航位移。
- 点击依据会筛选证据并定位到原文，支持搜索和恢复全部；「竞品原图」单独展示参考图片，与图片解析数量分开标注。竞品表读取当前报告对应的采集商品，价格为快照，不补造市场排名或缺失评分。
- `report.generate` 在八模块分析后增加独立的内容策划步骤，读取 `references/creative-brief-template.md`；返回5+8结构、校验证据ID和必需字段后才在事务中替换旧报告。暂时供应商错误最多重试失败阶段一次。
- 对大批次均匀抽取最多20件商品，评价选样优先保留已有的负面和混合解析，其余均匀选取；选样数量和文本截断限制写入risks。完整单品分析仍保留在productReports中。
- 结构化方案保存于 `AnalysisRun.reportJson.creativePlan`，含版本、数据量、脚本、证据、素材需求及研究正文。旧报告字段保留；原有采集表和数据库连接配置不变。
- 新导出包含完整策划及证据，导出缓存路径带reportHash，避免更新策划后仍读取旧文件。页面支持Markdown、HTML、JSON文件导出；智能问答上下文也包含主图与详情脚本。
- 本机猫粮、冲锋衣两份既有策划已按之前交付的研究内容分别导入对应报告，不通过运行时硬编码品类样例来替代新数据。导入前已备份本机数据库。
