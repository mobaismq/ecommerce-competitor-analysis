# 店透视采集插件内置化与自动加载架构方案

## 一、方案背景与核心痛点

当前版本的店透视 RPA 采集链路存在两个主要门槛：
1. **依赖用户预装插件**：用户电脑的 Chrome 必须事先安装好“店透视”扩展，否则页面上没有导出按钮，采集无法进行；
2. **依赖 macOS 特权勾选**：当前脚本依赖 AppleScript（`osascript`）向 Chrome 注入 JavaScript，必须手动在 Chrome 菜单栏勾选「查看」>「开发者」>「允许 Apple 事件中的 JavaScript」，容易引发用户困惑；
3. **跨平台兼容阻碍**：AppleScript 仅能在 macOS 运行，无法直接在 Windows 上使用。

---

## 二、终极架构目标：全自动内置 + CDP 免特权

通过 **“插件随包分发 + `--load-extension` 自动挂载 + Chrome CDP 协议免权限驱动”** 实现 0 门槛开箱即用：

```mermaid
graph TD
    User[用户点击客户端【开始采集】] --> Check[桌面端检查是否有可用 Chrome 调试实例]
    Check -->|未运行/未开启CDP| Launch[桌面端拉起专用 Chrome 实例]
    Launch --> Ext["参数1: --load-extension=<内置店透视插件目录>"]
    Launch --> Port["参数2: --remote-debugging-port=9222 (开启CDP)"]
    Launch --> Profile["参数3: --user-data-dir=<系统专属用户数据目录> (保留登录态)"]
    Ext & Port & Profile --> Browser[Chrome 浏览器就绪 (插件已自动加载)]
    Browser --> RPA[Python RPA 采集脚本通过 CDP (Playwright/WebSocket) 驱动]
    RPA --> Page[直接在页面上注入执行 JS，无需 AppleScript 授权]
    Page --> Export[模拟点击店透视导出按钮，自动归集 Excel]
```

## 三、Mac 与 Windows 系统差异对照

在跨平台落地时，必须在代码层面做好系统差异抽象与抹平：

| 维度 | macOS | Windows | 抹平策略 / 统一抽象接口 |
| :--- | :--- | :--- | :--- |
| **Chrome 可执行文件路径** | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` | `C:\Program Files\Google\Chrome\Application\chrome.exe`<br>或 `C:\Program Files (x86)\...` | 在 `findChromePath()` 中使用候选数组与 `existsSync` 探测匹配 |
| **持久化用户数据目录 (`user-data-dir`)** | `~/Library/Application Support/ecommerce-analysis/chrome-profile` | `%APPDATA%\ecommerce-analysis\chrome-profile`<br>即 `C:\Users\<user>\AppData\Roaming\...` | 使用 Electron 的 `app.getPath('userData')` 获取原生标准应用数据根 |
| **店透视插件内置打包路径** | `电商竞品分析.app/Contents/Resources/extensions/diantoushi` | `resources/extensions/diantoushi` | 打包后统一通过 `process.resourcesPath + '/extensions/diantoushi'` 访问 |
| **CDP 调试端口与通信** | `http://127.0.0.1:9222` | `http://127.0.0.1:9222` | **完全一致**（基于 HTTP/WebSocket 协议，原生跨平台） |
| **免权限要求** | **完全免勾选**「允许 Apple 事件中的 JavaScript」 | **原生支持**，无任何系统弹窗限制 | **彻底消灭操作系统与浏览器权限壁垒** |

---

## 四、方案实施路径

1. **阶段一（离线资产提取）**：在有店透视插件的电脑上提取解包产物，置入 `resources/extensions/diantoushi`；
2. **阶段二（打包工程配置）**：在 `electron-builder.yml` 的 `extraResources` 中加入 `extensions/` 映射；
3. **阶段三（运行时启动器注入）**：主进程 `chrome.ts` 启动 Chrome 时，动态拼装 `--load-extension` 与 `--remote-debugging-port=9222`；
4. **阶段四（采集脚本全面升级 CDP）**：采集脚本直接通过 CDP 操控 Chrome，废弃 `osascript` 依赖。
