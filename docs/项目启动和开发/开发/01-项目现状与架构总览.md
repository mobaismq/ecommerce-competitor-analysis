# 01 项目现状与架构总览

> 更新基准：2026-09，main-dev 分支。

## 1. 一句话定位

电商竞品分析系统：**Electron 原生桌面应用（唯一产品界面）+ NestJS 服务端（账号/权限/任务/报告/资产）**，数据形态**本地优先**。

## 2. 关键架构现状（AI 必须知道的事实）

### 2.1 桌面端：能力全量本地化，走 worker IPC

- 渲染层**不直接**做业务能力，统一走：渲染层 → 主进程 `worker-manager` → utility 子进程 `src/worker/`（IPC）→ 本地 SQLite（Prisma）+ 本地文件存储。
- 桌面端**没有内嵌 HTTP 后端**；业务能力（商品、采集分析、图库、生图、报告、平台发布等）都实现在 `apps/desktop/src/worker/*-capability.ts`。
- 桌面端本地库：`apps/desktop/data/desktop.db`（SQLite，`DESKTOP_DB_URL` 可覆盖）；每次 `pnpm dev` 的 predev 自动执行本地迁移与 prisma generate。

### 2.2 渲染层依赖服务端的只有「账户侧」

- 账号、登录、权限、店铺等接口走 `VITE_API_BASE_URL`（开发指向本地后端 `http://127.0.0.1:8787`，线上指向远程域名）。
- `apps/backend` 保留服务端全套模块（admin/auth/products/reports/storage/queue 等）；桌面端业务能力**不依赖**它，只有账户侧接口依赖。

### 2.3 本地/服务器能力边界（唯一判据）

| 能力 | 归属 |
|---|---|
| 账号、权限、店铺 | **服务器**（服务端 MySQL，Docker 起本地 3308） |
| 采集、店透视 RPA、凭证 | **本地**（桌面端 worker + 本机 Chrome/Python），不做服务端采集 |
| 图库、生图、报告、平台发布 | **本地**（worker + 本地存储） |
| 数据同步上传 | 可选（`SYNC_COLLECTION/REPORT/ASSET` 默认 false = 不主动上传） |

### 2.4 存储与数据落在哪

- 存储开关唯一事实源：`STORAGE_DRIVER`（backend 与 desktop 各自 .env），**默认 `local`**；腾讯云 COS 逻辑已实现但默认注释禁用，有明确上云需求再放开。
- 本地数据根目录：`~/.ecommerce`（配置/密钥）与 `~/ecommerce`（业务资产，如报告导出在 `~/ecommerce/users/<id>/reports`）。
- AI 能力落盘、图库字节流等均通过 StorageDriver 抽象，不私造存储路径。

### 2.5 AI 密钥与模型

- 用户个人自配密钥存**本机** `~/.ecommerce/users/<id>/config/ai-self.json`，API 不回传明文。
- 桌面端 env（`OPENROUTER_*`）作为**系统默认供应商**：个人自配优先 → 无则回落系统默认 → 都没有则**诚实报错**（不 Mock）。
- AI 配置页分「文本模型 / 生图模型」两类。

## 3. 给 AI 的行为约束

1. **唯一权威判据**：一个业务状态/数据判定只允许一处权威定义；前端严禁私造字段、逻辑冗余。
2. **防封号防资费**：涉及店透视（RPA）与大模型分析（Ark/DeepSeek/OpenRouter）的逻辑，本地测试必须用 `rpa_runs/` 历史离线样本或 Mock（`fake: true`），严禁高频真爬虫/真大模型。
3. **诚实报错**：外部能力缺失时如实报错 + 文案提示，严禁 Mock 冒充成功。
4. **改公共核心逻辑前**先评估影响面（可借助 codebase-memory-mcp / code-review-graph 等代码图谱工具）。
5. **验证门禁**：日常改动跑 `pnpm typecheck` + 相关单测；交付/提交前跑一次 `pnpm build`。
