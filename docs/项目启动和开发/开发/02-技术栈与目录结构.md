## 3. 「某类代码放哪」速查

| 要写的东西 | 放哪 | 不放哪 |
|---|---|---|
| 业务页面 | `apps/desktop/src/renderer/src/pages/` | 不建新顶层应用 |
| 可复用 UI 组件 | `renderer/src/components/` | 不要在 pages 里互相 import 私有组件 |
| 接口请求 | `renderer/src/api/`（账户侧 HTTP）；业务数据走 preload IPC，不写 fetch | 渲染层不得直连本地 SQLite/文件系统 |
| 业务能力（本地数据/文件/AI/采集） | `apps/desktop/src/worker/<域>-capability.ts` + `main/capability-handlers.ts` 注册 | 不要在主进程或渲染层内联实现能力 |
| 服务端接口 | `apps/backend/src/<module>/`（controller/service/dto） | 桌面业务能力不要写进 backend |
| 数据模型 | desktop：`apps/desktop/prisma/schema.prisma`；backend：`apps/backend/prisma/schema.prisma` | 两边各自独立，勿互相引用 |
| RPA 技能/脚本 | `skills/`（遵循 `apps/guidelines/` 规范） | |
| 一次性验证脚本 | 对应 app 的 `scripts/`（命名 `*-smoke.ts`） | |

## 4. 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 后端 API + Electron 桌面端一起起（日常开发） |
| `pnpm dev:desktop` / `pnpm dev:backend` | 分体单起 |
| `pnpm typecheck` | 全仓并发 tsc --noEmit（改完代码必跑） |
| `pnpm test` / `pnpm test:desktop` / `pnpm test:backend` | 单元测试 |
| `pnpm build` | 全仓编译（交付/提交前跑一次，日常勿频繁跑） |
| `pnpm check-env` | 环境自检（Node/pnpm/Electron/Python/Chrome/Prisma/Docker MySQL） |
| `pnpm --filter backend db:seed` | 刷新账号/权限/平台字典（幂等） |
| `pnpm --filter backend exec prisma studio` | 数据库可视化（localhost:5555） |
