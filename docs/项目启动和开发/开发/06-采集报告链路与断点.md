# 06 采集 → 分析报告 链路：当前逻辑与断点

> 更新基准：2026-09，main-dev 分支。
> **改这些代码前必读**：`run_diantoushi_rpa_cdp.py`、`collection-runner.ts`、`collection-handlers.ts`、`collection-importer.ts`、`AnalysisCollectPage.tsx`、`report-capability.ts`、以及 `CollectionJob / ProductSnapshot / ProductSkuSnapshot / ProductQaSnapshot / ProductReviewSnapshot / AnalysisRun` 相关表的任何改动。

## 1. 链路现状（已接通的）

```
AI数据采集页(AnalysisCollectPage)
   │  collection.start(...)        ← 主进程真实店透视 RPA，会真的打开浏览器爬
   │  collection.status(jobId)轮询 ← 解析 run.log 的 "=== batch item X/Y" 实时进度
   ▼
主进程 collection-runner / collection-handlers
   │  下载器返回结构化 products 清单（契约：最后一行 JSON，可含 products[]）
   │  一旦含 products → collection-importer.importCollectedProducts()
   ▼
本地 SQLite：CollectionJob + ProductSnapshot/SKU/QA/Review 四张快照表
   │  report.generate（MarketReportPage 已接）读取快照表 → 调真实 AI → 写 AnalysisRun
   ▼
报告页读取 AnalysisRun / AnalysisPriceBand / AnalysisInsight
```

- **采集**：`AnalysisCollectPage.tsx` 已从旧桩 `analysis.jobs.create`（只登记 queued、永不推进）改为走主进程真实 `collection:start`，页面 3000ms 轮询 `collection:status`，用 `parseRpaProgress` 解析 run.log 出进度条。**会真开浏览器**。
- **报告数据源桥**：`apps/desktop/src/main/collection-importer.ts` 缺失了 Report `generateReport` 依赖的 `CollectionJob`+四张快照表，本模块把它们补上了（对齐后端 `CollectionResultDto`，upsert 幂等）。这是报告管线唯一的数据入口。
- **离线样本/演示模式已删除**：不给用户交互提供 mock 采集；mock 只允许出现在自动化测试（例：`collection-importer.spec.ts` 用测试专用 mock 数据）。

## 2. 已解决的坑

- 桌面端此前**没有任何代码**写 `CollectionJob`/快照表 → `report.generate` 永远报"未找到本机采集数据"。现在 `collection-importer` 落库。
- AI数据采集页此前用 `analysis.jobs.create` 桩，不开浏览器、不推进、无数据。现在走真实 `collection:start`。
- 产品红线：**外部能力缺失/未接通时禁止 mock 冒充成功**；人工交互一律真实采集（详见 `01-项目现状与架构总览.md`、记忆 `honest-fallback-no-mock-redline`）。

## 3. 诚实边界（未闭环，需要真实环境才能完成）

> ⚠️ **这一块还没做完，同事接手时要知道。**

**真实店透视 CDP 爬虫 `run_diantoushi_rpa_cdp.py`：**
- 目前**导出的是 xlsx 文件**（商品数据 / SKU预览 / 问大家），且**单次运行只采集单个商品**（`choose_highest_sales_product` 挑销量最高那个导出）。
- **没有输出结构化 `products` 清单** → 所以**真实爬取 → 快照 → 报告 的"最后一英里"还没有自动接通**。

**要做、但必须在真实店透视环境验证（本机无法跑真实爬虫，故未硬改）：**
- 方案 A：给 `run_diantoushi_rpa_cdp.py` 补一个** structured products 清单输出**（把已拿到的商品元数据：`item_id→externalProductId`、标题、`href→productUrl`、`sales_count→sold` 整理成 `products[]`，放进脚本最后的 summary JSON）。管线契约已备好——**下载器一旦返回 `products`，就自动落快照出报告**（见 `collection-runner.ts` 下载阶段）。
- 方案 B：做一个 **xlsx → 快照 的导入步骤**（解析 `商品数据ID_*.xlsx` 等导出文件，含价格/SKU/问大家/评价），参考旧 `skills/mysql-import/load_to_mysql.py`。
- 注意：CDP 脚本单次单商品，要做"竞品分析报告"需要**多商品**数据——要么给爬虫补多商品采集（topN 循环导出），要么结合方案 B 一次导入整批导出文件。

**当前可接受的状态**（先顶着）：采集会真开浏览器并落数据（rpa_runs/ + 导出文件），但报告数据源需等爬虫补 `products` 清单后才能自动出；在补之前，`report.generate` 因读不到快照仍会诚实报错（不 mock 成功）。
