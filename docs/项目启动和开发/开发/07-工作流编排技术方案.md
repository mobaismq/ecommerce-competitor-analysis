# 07 工作流编排技术方案：LangGraph + 自研 Checkpoint

> 更新基准：2026-09，main-dev 分支。
> **改这些代码前必读**：`apps/desktop/src/worker/product-sets-graph.ts`、`detail-graph.ts`、`checkpoint-saver.ts`、`worker/index.ts` 里 `productSets.graph.run` / `productSets.detailGraph.run`，以及 `LangGraphCheckpoint / LangGraphCheckpointWrite` 两张表、`ProductImageSetsPage.tsx` / `APlusDetailPage.tsx` 里调用这些能力的生成逻辑。

## 1. 为什么选 LangGraph，以及 checkpoint 方案

- **编排引擎**：`@langchain/langgraph@1.4.17`（纯 JS，进程内 compile+invoke，不连 LangGraph server / LangSmith）。适合把「多步 + 扇出 + 部分失败 + 断点续跑 + 流式进度」的 AI 生成管线声明式建模成图。
- **checkpoint**：**没有**用用户最初点名的 `@langchain/langgraph-checkpoint-sqlite`，原因是它依赖原生模块 `better-sqlite3`，而本项目当前**没有** electron-rebuild / asarUnpack / install-app-deps 的原生模块打包机制（Prisma 的原生引擎在 `out/` 里都不存在，链路本就脆弱）。于是自研 `checkpoint-saver.ts`：实现 LangGraph 官方统一接口 `BaseCheckpointSaver`，**复用现有 Prisma 连本地 `~/.ecommerce/desktop.db`**，写 `LangGraphCheckpoint` / `LangGraphCheckpointWrite` 两张表。语义与官方 SqliteSaver 一致，且**零新增原生依赖**。
- **以后要换官方 SqliteSaver**：`BaseCheckpointSaver` 是统一接口，只需替换 `checkpoint-saver.ts` 的实现，业务代码不动；届时再补 electron-rebuild + asarUnpack 打包配置。

## 2. 已用 LangGraph 编排的场景

两张图都是「用 `Send` 动态扇出 + 节点内 try/catch 部分失败 + checkpoint 断点续跑 + `graph.stream` 节点级进度经 IPC 流式回显」：

### 2.1 商品主图套图 —— `productSets.graph.run`
- 入口：`worker/index.ts` → `runProductSetGraph`（`product-sets-graph.ts`）。
- 节点：`planPrompts`（LLM 策划各图位提示词）→ `Command({ update: { slots }, goto: [Send('generateOne', { slot })] })` 扇出 → 每个 `generateOne` 图生图 + 落 `GeneratedAsset`。
- 页面：`ProductImageSetsPage.handleGenerateAll` 调用该能力，`onStream` 消费 `node:generateImage` 事件逐图位回显。jobId 即 thread_id，崩溃后同 jobId 可续跑。

### 2.2 详情图批量生成 —— `productSets.detailGraph.run`
- 入口：`worker/index.ts` → `runDetailGraph`（`detail-graph.ts`）。
- 节点：`dispatch`（按已策划好的模块列表 `Send` 扇出）→ 每个 `generateOne` 图生图 + 落库。
- 页面：`APlusDetailPage.handleBatchGenerateAll` 调用该能力，`onStream` 消费 `node:generateImage` 事件按 `instanceId` 回显。

### 2.3 流事件协议（worker → 渲染层）
经 `ctx.emit` 转发，`event.type` 为自由字符串：
- `{ type: 'node', data: { jobId, node: 'planPrompts'|'generateImage', status, slotId/instanceId, imageUrl, error } }`
- `{ type: 'done', data: { jobId, failedCount } }`

> ⚠️ 现有 `onStream` 是**全局广播、不区分请求**（无 msgId 过滤），同一页面并发多个 LangGraph 调用会串流。目前页面都是单并发调用，够用；并发增强是已知限制。

## 3. 还没迁到 LangGraph 的场景（同事可照做）

- **详情图规划阶段**：`APlusDetailPage.handlePlanWorkflow` 仍走 `productSets.generateDetailWorkflow` 单次 LLM 调用。刻意保留——用户在 strategy 步会**审改提示词**，这是人工介入点。后续可迁成 LangGraph 的 `interrupt()`（HITL）节点。
- **逐图「改图 / 编辑文字 / 智能改尺寸」**：仍是页面直接调 `image.generate`（单图、即时、非批量），暂未迁。若要做「改图历史/版本化/可恢复」，可用 `interrupt()` 建模。
- **其他 AI 多步管线**：`dataAgent.chat`、`report.generate` 等仍是单次/命令式。符合「多步+扇出+可恢复」特征时可套本方案。

## 4. 给同事的「照做模板」：新增一个 LangGraph 编排能力

1. **建图**：仿 `product-sets-graph.ts` / `detail-graph.ts`，用 `StateGraph(Annotation.Root({...}))` 声明状态（数组字段用 reducer 合并），节点返回 `Command({ update, goto: [Send] })` 扇出；逐项节点内 try/catch 处理部分失败，`code==='ABORT'` 向上抛以中止整图供续跑。
2. **编译**：`graph.compile({ checkpointer: deps.checkpointer })`，thread_id 即业务 jobId。
3. **能力注册**：在 `worker/index.ts` `createBuiltinHandlers` 里加 handler，接收 `ctx` 并把节点级事件 `ctx.emit(...)` 转发；deps 用闭包捕获 userId / 参考图 / 设置（**别把大对象放图状态里**，否则 checkpoint 会很大）。
4. **页面接线**：调能力前先 `capabilities.onStream` 订阅，按 `event.data.node` 消费更新本地状态，`invoke` 返回后 `unsub()`。
5. **离线单测**：注入 fake `planPrompts`/`generateImage` + `PrismaCheckpointSaver`（临时库），至少覆盖「全量成功 / 部分失败不中断 / ABORT 后同 jobId 恢复补跑」。**测试进程注意**：prisma 是模块级单例，多 DB 写入测试须各独立进程，且整份 spec 用同一个临时库（`beforeAll` 一次迁移），不能在 `beforeEach` 换 `ECOMMERCE_DATA_ROOT`。

## 5. LangGraph JS v1 的关键坑（已踩平）

- `graph.stream(input, options)` 是**异步**的（返回 `Promise<IterableReadableStream>`）；config 的 `configurable.thread_id` 和 `streamMode` 都放 options 里。
- **`Send` 分支不继承父状态**：分支里读不到父级的 `slots`/`modules` 数组，必须把目标项对象放进 `Send` 载荷（`{ slot }` / `{ module }`），分支返回时再写回共享数组（经 reducer 汇总）。
- `Command({ update, goto })` 动态 goto 的目标节点要在 `.addNode(name, node, { ends: [目标] })` 声明，否则报 `UNREACHABLE_NODE`。
- `getCheckpointId` **未从** `@langchain/langgraph` re-export，自己在 saver 里读 `config.configurable.checkpoint_id`。
- `@langchain/core` 需加为**直接依赖**（pnpm strict 下传递依赖不可见），供 `@langchain/core/runnables` 的 `RunnableConfig`。
- 默认 serde `JsonPlusSerializer` 的 `dumpsTyped` 返回 `[type, Uint8Array]`；`checkpoint-saver.ts` 统一按 `type:base64` 落库，读回时按 type `loadsTyped`。
- 并发并行分支在同一步的 stream update 可能是数组，翻译事件时用 `Array.isArray(update) ? update : [update]` 兜底。

## 6. checkpoint 表与迁移

- 表：`LangGraphCheckpoint`（threadId+checkpointNs+checkpointId 唯一）、`LangGraphCheckpointWrite`（+taskId+writeIdx 唯一）。
- 迁移：`apps/desktop/prisma/migrations/20260925_langgraph_checkpoint/migration.sql`；`scripts/apply-local-migration.mjs` 已扩展状态探测与幂等执行（`predev` 自动跑）。新增 checkpoint 表前要在该脚本里加探测，否则老库不建表。
- checkpoint 行会随每次运行累积；暂未暴露删除。单用户桌面可接受，后续可在页面加「清空历史 job」时调 `deleteThread`。

## 7. 后续可改造方向

> 以下两项**本轮不做**，仅作为同事日后的落地规格，供按需实施。

### 7.1 统一 fan-out helper（消除两张图的重复）
`product-sets-graph.ts` 与 `detail-graph.ts` 结构高度同构——都是「**一个分派入口节点 → `Send` 按项扇出 → 每个 `generateOne` 图生图（节点内 try/catch 部分失败 + ABORT 中止 + 幂等跳过 done）→ checkpoint + stream 回显**」，仅 item 字段名不同（`slot.id` vs `module.instanceId`）。日后再加「第三个图生图工作流」前，先抽通用构建器：

```
// 目标签名（示意，落地时以 product-sets-graph/detail-graph 现状为准校准类型）
buildFanOutGraph<Item, Asset>(args: {
  itemKey: (item: Item) => string               // slot.id / module.instanceId
  stateDef: Annotation.Root<{ items: Item[]; assets: Asset[]; item?: Item }>
  generateOne: (input: { item: Item; jobId: string }) => Promise<{ url: string; asset: Asset }>
  checkpointer: BaseCheckpointSaver
  emitNodePos: 'slotId' | 'instanceId'          // 流事件里回传的 item 标识字段名
})
```
然后 `product-sets-graph.ts`（含其 `planPrompts` 节点仍保留）+ `detail-graph.ts` 都改为基于该 helper 组装，仅保留各自的 item 类型与 `planPrompts`/`dispatch` 差异。**验收**：两个图的 6 个离线单测不变仍通过；`pnpm typecheck` 通过。

### 7.2 `interrupt()` HITL（把人工介入建模进图）
现状里两处人工介入仍由页面命令式处理（未进图）：
- **详情图规划审改**：`handlePlanWorkflow` 产出提示词后，用户可在 strategy 步逐模块改文案再点「生成详情图」。
- **逐图改图 / 编辑文字 / 智能改尺寸**：`ProductImageSetsPage` / `APlusDetailPage` 的单图操作仍直接 `image.generate`。

落地思路：
1. 把「单图重绘/改字/改尺寸」建模成独立节点，节点内 `interrupt()` 暂停并带上当前图与可选项；`__interrupt__` 经 IPC 回传「在等什么」，页面渲染改图面板。
2. 用户确认后调 `Command({ resume: 用户输入 })` 续跑该节点。
3. **注意**：`interrupt()` 前产生的副作用必须幂等（恢复会重入），不要用 try/catch 包 `interrupt()`。
4. 建议先从「详情图规划审改」入手（单点、无扇出），跑通后再推广到逐图操作。

### 7.3 其余
- **打包分发**：electron-builder 目前 `files` 只含 `out/**`，不含 node_modules；正式打包分发时 `@langchain/langgraph`、`@langchain/core` 需随包（当前 dev 阶段不受影响）。
- **并发流隔离**：给 `onStream`/preload 加 msgId 过滤，解决全局广播串流限制。
