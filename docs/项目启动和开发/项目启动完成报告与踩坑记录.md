## 三、MySQL 容器的两点注意

1. **是 amd64 镜像，跑在 QEMU 模拟下**（本机 arm64）。华为 SWR 的 `ddn-k8s/docker.io/library/mysql:8.4` 只有 amd64 版本。
   实际运行正常（已 healthy、迁移与 seed 均通过），但性能有损耗。启动日志里的
   `InnoDB: Linux Native AIO interface is not supported` 是模拟环境下的正常告警，可忽略。
2. 首次 `db:migrate` 曾报 `P1017: Server has closed the connection` —— 那是容器还在
   **临时实例**初始化阶段（此时健康检查已通过，容易误判）。等日志出现
   `ready for connections ... port: 3306` 后再执行迁移即可。

## 四、踩到的 4 个坑（换机器复现时直接照此处理）

### 1. `ELECTRON_RUN_AS_NODE=1` 导致 Electron 起不来（最容易误判为项目 bug）

现象：`pnpm dev` 后端正常，桌面端崩溃：

```
Error: Please specify the `projectName` option.
    at new ElectronStore (.../electron-store@10.1.0/index.js:69:3)
```

根因：**不是项目问题**。DSH 自身跑在 Electron 里，环境变量 `ELECTRON_RUN_AS_NODE=1`
被继承到我的 shell，于是 `electron` 二进制被当成普通 Node 启动，
`require('electron')` 拿不到 `app` / `ipcMain`，`electron-store` 取不到 `cwd` 就抛错。

解决：`env -u ELECTRON_RUN_AS_NODE pnpm dev`。
（在自己终端里不会有这个变量，直接用 `pnpm dev` 即可。）
仓库里 `scripts/check-env.mjs` 也专门 `delete env.ELECTRON_RUN_AS_NODE`，是同一个已知问题。

### 2. Prisma 迁移历史自相冲突，`migrate dev` 必然失败

`20260909085940_init` 与 `20260913000000_rebuild_database` **都** `CREATE TABLE Tenant`，
`migrate dev` 在 shadow database 重放全部迁移时报 `P3018 / 1050 Table 'Tenant' already exists`。

确认 `init` 是历史遗留基线：它建的 `AnalysisJob`、`RpaTask` 两张表**已不在当前 schema**（当前 37 个模型）。
且 `rebuild_database` 建了 35 张表，是完整的重建。

全新库的正确初始化顺序：

```bash
cd apps/backend
pnpm exec prisma generate
pnpm exec prisma migrate resolve --applied 20260909085940_init
pnpm exec prisma migrate deploy
pnpm --filter backend db:seed
```

> 注意：`db:migrate`（即 `prisma migrate dev`）在后续开发中仍会因该历史冲突失败，
> 属于仓库既有问题，需要时建议让同事重做迁移历史。

### 3. 网络：多个源在本机不可用

| 目标 | 实测 |
|---|---|
| `github.com` 大文件 | ~30 KB/s（317MB 的 Colima 镜像靠 16 线程分段下载才拿下，已校验 `IMAGE_OK`） |
| `registry.npmjs.org` | 连接建立后**不传数据**（`pnpm install` 卡死 36 分钟无进展） |
| `desktop.docker.com` | 连接被重置 |
| `ghcr.io` / USTC / npmmirror / 华为 SWR | 正常，速度快 |

已做的加速配置（**均可删除回退**）：

| 文件 | 作用 |
|---|---|
| `~/.npmrc`（新建） | npm/pnpm 走 `registry.npmmirror.com`，Electron 等二进制走 npmmirror |
| `~/.docker/config.json`（新建） | 让 `docker compose` 子命令可用（Homebrew 插件路径） |
| `~/.colima/default/colima.yaml` | Docker Hub 加速（daocloud / 1ms.run / 1panel；对 mysql 无效，仅 alpine 这类小镜像生效） |
| brew 环境变量 | 当次使用 `HOMEBREW_API_DOMAIN` / `HOMEBREW_BOTTLE_DOMAIN` 指向 USTC 镜像 + `HOMEBREW_NO_AUTO_UPDATE=1`（不关自动更新会卡在无法访问的 github.com） |

### 4. 端口 5173 / 8787 被无关旧进程占用

- `5173` 已被一个旧的 vite 进程（pid 2605，属于仓库里的 `app/` 老目录）占用，
  electron-vite 自动改用 **5179**，属正常行为。
- `8787` 上另有一个跑了 25 天的 `node server/index.js`（pid 38783，IPv6 通配）与后端并存；
  访问 `127.0.0.1:8787` 会命中我们的后端（已验证 health/login 均正确）。
  若后续出现莫名其妙的接口异常，可先 `kill 38783`。

## 五、仍可选未装的一项：内置 Python（指南第 11 项）

不影响界面与后端开发，`pnpm check-env` 会显示 `FAIL embedded Python`（预期）。

内置运行时由 `apps/desktop/scripts/prepare-python.mjs` 从 GitHub Releases 下载（约 50MB，
本机 GitHub 带宽约 30KB/s，单连接需约 30 分钟）。三选一：

1. **暂不装**（当前状态）。
2. **复用本机已有 Python**：在 `apps/desktop/.env` 设
   `PYTHON_PATH=/Users/tiantainxianghui/.local/share/uv/python/cpython-3.12-macos-aarch64-none/bin/python3.12`
3. **完整安装**：
   ```bash
   pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
   pnpm --filter desktop prepare-python
   ```

另：安装时 pnpm 提示 `Ignored build scripts: electron-winstaller@5.4.0`，仅影响打包 Windows 安装包，
本地开发无需处理；需要时执行 `pnpm approve-builds`。
