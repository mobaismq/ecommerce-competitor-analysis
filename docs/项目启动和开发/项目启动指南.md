# 项目启动指南（AI 可直接照此执行）

> **用法**：对 AI 说「根据 `docs/项目启动和开发/项目启动指南.md` 把项目跑起来」即可。
> **执行原则（给 AI）**：先逐项检查本机现状，**已有的一律跳过、绝不重装**；缺的能自动装的（依赖、初始化、下载运行时）AI 自己执行；装不了的桌面软件（Node、Docker、Chrome）给出官方下载地址引导用户手动安装；全部就绪后执行 `pnpm dev` 启动并自检。

## 0. 项目形态一句话

pnpm monorepo，两个业务包 + 一个内容目录：

- `apps/desktop`：Electron 桌面应用（唯一产品界面，业务 UI 全在渲染层，能力跑在本地 worker + 本地 SQLite）
- `apps/backend`：NestJS 服务端（账号/权限/任务/AI 报告/资产存储；本地开发跑在 `127.0.0.1:8787`，MySQL 用 Docker 起在 `3308`）
- `apps/guidelines`：RPA 采集遵循的规范文档（非代码包）
- `apps/legacy`：旧版单体应用，**不要在里面开发**

## 1. 环境检查（按表逐项执行，通过即跳过）

| # | 检查项 | 检查命令 | 通过标准 | 缺失时的处理 |
|---|---|---|---|---|
| 1 | Node.js | `node -v` | v20 及以上 | **引导用户**下载 LTS 安装包：https://nodejs.org/zh-cn ，装完重开终端再查 |
| 2 | pnpm | `pnpm -v` | 10.x（项目锁定 10.33.4） | **AI 执行**：`corepack enable && corepack prepare pnpm@10.33.4 --activate`；corepack 不可用则 `npm install -g pnpm@10` |
| 3 | Docker | `docker info` | 命令可用且 daemon 运行 | **引导用户**安装 Docker Desktop：https://www.docker.com/products/docker-desktop/ ，装完启动它 |
| 4 | 项目依赖 | `test -d node_modules && echo ok` | 输出 ok | **AI 执行**：`pnpm install` |
| 5 | 后端配置 | `test -f apps/backend/.env` | 文件存在 | **提醒用户找同事要** `apps/backend/.env` 配置文件，放到 `apps/backend/` 下（该文件含真实密钥、不入 git）；同事暂时给不了时应急占位：`cp apps/backend/.env.example apps/backend/.env` |
| 6 | 桌面端配置 | `test -f apps/desktop/.env` | 文件存在 | **提醒用户找同事要** `apps/desktop/.env` 配置文件，放到 `apps/desktop/` 下；同事暂时给不了时应急占位：`cp apps/desktop/.env.example apps/desktop/.env` |
| 7 | MySQL 容器 | `docker compose ps mysql` | 状态 Up 且 healthy | **AI 执行**：`docker compose up -d mysql`，等健康检查通过（约 10~30 秒） |
| 8 | 数据库表 | 尝试 `pnpm --filter backend exec prisma migrate status` | 无 "have not yet been applied" 报错 | **AI 执行**（仅首次/提示缺表时）：`pnpm --filter backend db:migrate` 然后 `pnpm --filter backend db:seed` |
| 9 | 桌面本地库 | `test -f apps/desktop/data/desktop.db` | 文件存在 | 一般无需手动：`pnpm dev` 的 predev 会自动迁移。确认缺库时 **AI 执行**：`pnpm --filter desktop db:init` |
| 10 | Chrome（RPA 用） | macOS 查 `/Applications/Google Chrome.app`；Win 查 `C:/Program Files/Google/Chrome` | 找到 | 仅跑采集/RPA 功能需要。**引导用户**安装：https://www.google.com/chrome/ |
| 11 | 内置 Python（RPA/图片工具用） | `test -x apps/desktop/resources/python/bin/python3`（Win 为 `.../python.exe`） | 可执行 | 可选项，不影响界面开发。需要时 **AI 执行**：`pnpm --filter desktop prepare-python`（自动从 GitHub 下载 3.12，约几十 MB）；或在 `apps/desktop/.env` 配 `PYTHON_PATH` 指向系统 python3 |

> 检查技巧：第 1~7 项决定能不能起；第 8~9 项首次必做；第 10~11 项只影响 RPA 采集与图片工具，界面开发可先跳过。

## 2. 一键初始化（仅首次；已初始化过的机器跳过本节）

上面 5~9 项缺失时，可等价地跑一条总命令：

```bash
pnpm setup
# 等价于：docker compose up -d mysql && pnpm install
#        && backend db:migrate && backend db:seed && desktop db:init && pnpm check-env
```

注意 `pnpm setup` **不包含** `.env` 准备（第 5、6 项）：这两份文件含真实密钥、不入 git，缺失时先提醒用户找同事要，应急再用 `.env.example` 拷贝占位。

## 3. 启动（日常只需这一步）

**环境检查全部通过后，直接执行：**

```bash
pnpm dev
```

它会同时拉起后端 API 与 Electron 桌面客户端（concurrently）。按需分体启动：

```bash
pnpm dev:backend    # 仅后端 API，http://127.0.0.1:8787（全局前缀 /api）
pnpm dev:desktop    # 仅桌面客户端（需后端 API 已在运行）
```

**启动成功判据**（AI 逐条确认）：

1. 终端 backend 日志正常监听 8787，无 Prisma/MySQL 连接报错
2. Electron 应用窗口弹出（渲染层 dev 服务在 5173，由 electron-vite 自动管理）
3. 登录页可打开，用下方默认账号能登录成功

**本地默认登录账号**（本地数据库，首次 `db:seed` 初始化）：

| 角色 | 账号 | 密码 |
|---|---|---|
| 管理员 | `admin` | `admin654321` |
| 超级管理员 | `super_admin` | `admin654321` |

> 以上是本地开发默认值；若同事给的 `.env` 改过 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 等变量，以 `.env` 为准，重跑 `pnpm --filter backend db:seed` 即可刷新账号（幂等可重跑）。

## 4. 启动后自检（可选但推荐）

```bash
pnpm check-env
```

逐项输出 PASS/FAIL（Node / pnpm / Electron / Python / Chrome / Prisma / Docker MySQL）。出现 FAIL 对照第 1 节表格补齐即可；「embedded Python」「system Chrome」为 FAIL 不影响界面与后端开发。

## 5. 常见问题速查

| 现象 | 处理 |
|---|---|
| 端口被占：3308 / 8787 / 5173 | `lsof -i :端口号` 找到占用进程；3308 冲突可改 `docker-compose.yml` 与 `apps/backend/.env` 的 `DATABASE_URL` 端口保持一致 |
| MySQL 健康检查一直不通过 | `docker compose ps` 看状态；`docker compose down && docker compose up -d mysql` 重试（volume 会保留数据） |
| Prisma 报 schema 未生成 | `pnpm --filter desktop db:generate`（正常情况下 `pnpm dev` 的 predev 会自动执行） |
| 登录报网络错误 | 确认 `apps/desktop/.env` 的 `VITE_API_BASE_URL` 指向 `http://127.0.0.1:8787` 且后端已启动 |
| Electron 装不上（网络） | 可设置镜像 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 后重跑 `pnpm install` |

## 6. 启动后给用户的一句话

- 数据存哪：业务数据在本地 `apps/desktop/data/desktop.db` 与用户目录 `~/.ecommerce`、`~/ecommerce`；服务端数据在 Docker MySQL
- 登录账号：见第 3 节「本地默认登录账号」（`admin` / `super_admin`，默认密码 `admin654321`）
- 下一步开发规范：见同目录 [开发/README.md](./开发/README.md)

## 7. AI 红线（启动验证阶段同样适用）

- 本地测试/验证**禁止**高频触发真实爬虫与真实大模型：店透视（RPA）与大模型分析一律用 `rpa_runs/` 历史离线样本或 Mock（`fake: true`），防封号、防资费
- 外部能力缺失时**诚实报错**并提示文案，严禁 Mock 冒充成功
