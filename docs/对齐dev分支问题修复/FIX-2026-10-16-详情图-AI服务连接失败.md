## 反馈

点击“生成详情页规划和提示词”后，[左侧显示错误](./images/2026-10-16-详情图-AI服务连接失败.png)：`Error invoking remote method 'capability:invoke': Error: fetch failed`。

## 排查结论

本次错误与先前的“详情页规划返回为空”不同：当前请求在连接 AI 服务时已失败，没有收到模型响应。详情图工作流先分析上传商品图，再生成规划和提示词；任一步的网络请求失败都会使流程终止，规划空响应重试无法处理连接失败。

当前本机 AI 配置指向 `openrouter.ai`。在同一台机器上，不携带 API Key 的连通性检查结果如下：

- Node `fetch` 连接 `openrouter.ai:443` 返回 `UND_ERR_CONNECT_TIMEOUT`（10 秒连接超时）。
- 系统代理为 Clash Verge 的 `127.0.0.1:7897`。显式通过该代理访问 OpenRouter：代理 CONNECT 成功，但 TLS 握手超时；访问 `api.openai.com` 同样超时。
- 显式通过同一代理访问 `www.apple.com` 返回 HTTP 200，说明本机代理端口可用，故障集中在当前 AI 服务的出站链路或其代理规则/节点，尚不能仅凭这些测试断定是哪个节点失效。

桌面端 Worker 当前使用 Node 原生 `fetch`，未显式接入 macOS 系统代理；即使补上代理接入，当前显式代理测试仍无法连通 OpenRouter。因此应先在 Clash Verge 中切换或修复可访问 OpenRouter 的网络节点/规则，再重新测试详情页规划。恢复后若浏览器能访问但桌面端仍超时，需要继续处理 Worker 的代理接入。

## 验证边界

本次仅完成代码调用链与本机网络排查，没有更改生成逻辑，也未能在当前网络状态下完成真实 AI 请求。无需更换或公开 API Key；现有证据指向连接失败，而非密钥、额度或提示词错误。
