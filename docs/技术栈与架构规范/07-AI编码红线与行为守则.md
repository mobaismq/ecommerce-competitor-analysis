# 七、AI 编码核心红线与行为守则

所有协助本项目开发的 AI Agent 与工程师均须无条件遵守以下四大准则：

---

## 1. 唯一权威判据铁律
- **原则**：一个业务状态或数据判定只能有且仅有一处权威定义。
- **要求**：
  - 严禁在前端硬编码私有判定或冗余逻辑；
  - 数据模型字段统一以服务端 Prisma Schema 或主进程 Preload 契约为准；
  - 避免在不同组件中重复定义同义但结构微调的 interface，优先提取或复用权威类型。

---

## 2. 防爬虫封号与防 Token 消耗红线
- **原则**：绝不能在测试中浪费用户生产资源或引起第三方账号风险。
- **要求**：
  - 涉及店透视（RPA）与大模型分析（Ark / DeepSeek）的逻辑，**本地测试必须优先使用历史离线样本数据（`rpa_runs/`）或 Mock 数据（`fake: true`）**；
  - 严禁在自动化测试、冒烟测试或循环脚本中频繁触发真实爬虫或云端大模型 API。

---

## 3. 客观测验取证原则
- **原则**：以客观真实数据说话，杜绝主观猜测。
- **要求**：
  - 交付任务或修复 Bug 时，必须附带真实命令运行输出（如 `pnpm typecheck` exit code 0、单元测试全部通过日志）；
  - 严禁用“理论上已修复”、“应该没问题”等主观套话交卷。

---

## 4. 组件库纯洁性守则
- **原则**：严格保障前端 UI 代码的规范与统一。
- **要求**：
  - 前端一律使用 **Arco Design React**（`@arco-design/web-react`）原生组件；
  - 禁止混入 Ant Design、Element 或 MUI 专有属性或语法；
  - 杜绝任意虚构图标名（先查 Arco 官方图标、Lucide 或 Morphicons）；
  - 遇到类型推导冲突时，通过标准 TypeScript 联合类型或合理收窄解决，杜绝滥用 `any`。
