# 后端服务手动部署与运维指引

> 适用场景：初次在服务器拉取代码初始化、修改重要配置或离线排查时使用。

---

## 1. 部署架构概览

```
[客户端/外部流量] 
        │
        ▼ (Port 80/443)
[Nginx 反向代理] 
        │ proxy_pass (proxy_buffering off - 保障 SSE 流式传输)
        ▼ (Port 8787 本地回环)
[PM2 守护进程] ──> [NestJS 后端 (main.js)]
                            │
                            ├──> [MySQL 8 本地库 3306 (ecommerce_competitor)]
                            └──> [腾讯云 COS 对象存储]
```

---

## 2. 初始部署全流程步骤

### 步骤 1：全局安装 pnpm 并创建发布目录
登录服务器：
```bash
ssh root@118.25.40.19
```
执行环境初始化：
```bash
npm install -g pnpm
mkdir -p /var/www && cd /var/www
```

### 步骤 2：克隆仓库与编译构建
```bash
cd /var/www
# 使用带有权限的 GitHub 访问凭证拉取代码
git clone https://github.com/mobaismq/ecommerce-competitor-analysis.git ecommerce-app
cd ecommerce-app

# 安装依赖
pnpm install

# 编译后端（服务端仅需编译 NestJS 后端）
pnpm --filter backend build
```

### 步骤 3：配置服务端生产环境变量
```bash
cd /var/www/ecommerce-app/apps/backend
cp .env.example .env
nano .env   # 或 vi .env
```
重点配置项清单：
```dotenv
# ===== 基础服务 =====
PORT=8787
HOST=127.0.0.1
NODE_ENV=production

# ===== 数据库连接 =====
# 注意：密码替换为此前 MySQL 初始化时的实际密码
DATABASE_URL="mysql://ecommerce:你的数据库密码@127.0.0.1:3306/ecommerce_competitor"

# ===== 鉴权 Token 密钥 =====
# 必须为 32 位以上随机串，切忌使用默认值
JWT_SECRET=生成的32位以上随机字符安全串
JWT_EXPIRES_IN=7d

# ===== 存储驱动 =====
# 初期或本地开发设为 local；启用腾讯云 COS 时改为 oss 并填入以下参数
STORAGE_DRIVER=local

# 若启用 COS，按以下填入：
# STORAGE_DRIVER=oss
# OSS_REGION=ap-shanghai
# OSS_BUCKET=ecommerce-assets-prod-1305526906
# OSS_ENDPOINT=ecommerce-assets-prod-1305526906.cos.ap-shanghai.myqcloud.com
# OSS_ACCESS_KEY_ID=你的腾讯云SecretId
# OSS_ACCESS_KEY_SECRET=你的腾讯云SecretKey

# ===== AI 接口 =====
AI_KEY_MODE=platform
OPENROUTER_API_KEY=你的生产OpenRouterKey
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
```

### 步骤 4：执行 Prisma 数据库表结构迁移
```bash
cd /var/www/ecommerce-app
pnpm --filter backend exec prisma migrate deploy
```

### 步骤 5：使用 PM2 启动后端服务
```bash
cd /var/www/ecommerce-app
# 启动进程
pm2 start apps/backend/dist/src/main.js --name backend

# 保存进程列表并注册操作系统开机启动
pm2 save
pm2 startup
```

本地健康检查自测：
```bash
curl -i http://127.0.0.1:8787/api/health/ready
# 期望返回 HTTP/1.1 200 OK
```

### 步骤 6：配置 Nginx 代理与静态转发
创建配置文件 `/etc/nginx/conf.d/ecommerce.conf`：
```nginx
server {
    listen 80;
    server_name _; # 后续绑定域名时替换为实际域名，如 api.yourdomain.com

    # 请求体限制增大（适应图片、报告上传）
    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;

        # 保持连接与真实客户端 IP
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 重点：关闭缓冲区，确保 AI 任务与 SSE 消息实时下发给客户端
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}
```

测试并重载 Nginx：
```bash
nginx -t
systemctl enable --now nginx
systemctl reload nginx
```

验证公网访问（在本地或浏览器访问）：
```bash
curl -i http://118.25.40.19/api/health/ready
```

## 3. 日常维护常用命令速查

| 操作 | 命令 |
|---|---|
| 查看后端实时日志 | `pm2 logs backend` |
| 重启后端服务 | `pm2 reload backend`（无缝重启） |
| 查看系统资源占用 | `pm2 monit` 或 `htop` |
| 检查 Nginx 错误日志 | `tail -f /var/log/nginx/error.log` |
| 检查 MySQL 运行状态 | `systemctl status mysqld` |
