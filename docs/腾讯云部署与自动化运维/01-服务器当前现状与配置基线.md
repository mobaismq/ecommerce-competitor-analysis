## 3. 防火墙与安全策略

### 3.1 腾讯云控制台防火墙规则（已验证确认）

当前安全组防火墙策略配置标准严谨：

| 协议 | 端口 | 来源 | 状态 | 作用 |
|---|---|---|---|---|
| **TCP** | `22` | 全部 IPv4 | **允许** | SSH 远程登录维护、GitHub Actions 自动部署 |
| **TCP** | `80` | 全部 IPv4 | **允许** | 外部 Web HTTP 访问、Let's Encrypt 证书验证通道 |
| **TCP** | `443` | 全部 IPv4 | **允许** | 外部 Web HTTPS 安全访问 |
| **ICMP** | `ALL` | 全部 IPv4 | **允许** | 允许 Ping，便于网络联通诊断 |

> 🔒 **安全准则**：
> 1. 后端端口 `8787` 和 MySQL 端口 `3306` **严禁直接放行公网**，仅在服务器本地（`127.0.0.1`）监听。
> 2. 外部流量统一通过 Nginx 80/443 进入，经反向代理转到 8787，安全且支持 SSL 加密与流量控制。

## 4. SSH 免密登录机制说明

当前本机可直接执行 `ssh root@118.25.40.19` 免输密码登录，其底层机制为**非对称密钥认证（Asymmetric Public-Key Authentication）**：

1. **没有在任何地方明文存储服务器 root 密码**。
2. **本地 Mac**：持有私钥文件 `~/.ssh/id_ed25519`（权限 `600`，严格受限，只有本机用户可读，绝不外发）。
3. **云端服务器**：在 `/root/.ssh/authorized_keys` 中登记了由 `ssh-copy-id` 写入的公钥：
   ```text
   ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIBnEeMHfNqgR06OCsdw6HbL5eposM2n63MIqzAoP9fxo lixiaowei5526@dingtalk.com
   ```
4. **认证握手原理**：
   - 客户端连接服务器时声明自己的公钥标识；
   - 服务器生成一个随机串（Challenge），用服务器上的公钥加密后发送给 Mac；
   - 本地 Mac 使用私钥解密并回传数字签名；
   - 服务器验证签名成功即放行登录。整个过程不需要密码，且即使公网抓包也无法反推私钥。
